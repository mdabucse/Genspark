# Docker Swarm 

## Introduction

Docker Swarm is Docker's native container orchestration tool that allows multiple Docker hosts to work together as a single cluster. It helps deploy, manage, scale, and monitor containerized applications across multiple machines.

---

## Key Concepts

### Cluster

A group of Docker hosts that work together as a single system.

### Node

A machine participating in the swarm.

Types of nodes:

* Manager Node
* Worker Node

### Manager Node

Responsible for:

* Cluster management
* Scheduling containers
* Maintaining swarm state
* Handling service deployments

### Worker Node

Responsible for:

* Running containers
* Executing tasks assigned by manager nodes

### Service

Defines the desired state of an application running in the swarm.

Example:

* Number of replicas
* Network configuration
* Image used

### Task

A running container assigned to a node.

### Replica

Multiple copies of the same container running for high availability and load balancing.

---

## Swarm Architecture

```text
                 Manager Node
                      |
        -----------------------------
        |                           |
   Worker Node 1              Worker Node 2
        |                           |
   Container A                 Container B
```

---

## Initializing a Swarm

Create a new swarm cluster:

```bash
docker swarm init
```

View the join token:

```bash
docker swarm join-token worker
```

---

## Joining a Worker Node

Run the command generated by the manager:

```bash
docker swarm join \
--token <TOKEN> \
<MANAGER-IP>:2377
```

---

## Node Management

List all nodes:

```bash
docker node ls
```

Inspect a node:

```bash
docker node inspect <NODE_ID>
```

---

## Service Management

Create a service:

```bash
docker service create \
--name nginx-service \
--replicas 3 \
-p 80:80 \
nginx
```

List services:

```bash
docker service ls
```

View service details:

```bash
docker service inspect nginx-service
```

View running tasks:

```bash
docker service ps nginx-service
```

---

## Scaling Services

Increase replicas:

```bash
docker service scale nginx-service=5
```

Decrease replicas:

```bash
docker service scale nginx-service=2
```

---

## Updating Services

Update image version:

```bash
docker service update \
--image nginx:latest \
nginx-service
```

Docker performs rolling updates without downtime.

---

## Docker Stack

A stack allows deployment of multiple services using a Compose file.

Example:

```yaml
version: "3.8"

services:
  web:
    image: nginx
    ports:
      - "80:80"
    deploy:
      replicas: 3
```

Deploy stack:

```bash
docker stack deploy -c docker-compose.yml myapp
```

List stacks:

```bash
docker stack ls
```

Remove stack:

```bash
docker stack rm myapp
```

---

## Load Balancing

Docker Swarm automatically distributes incoming requests among available replicas using its routing mesh.

Benefits:

* High availability
* Better resource utilization
* Automatic traffic distribution

---

## Self-Healing

If a container fails:

* Swarm detects the failure.
* Automatically creates a replacement container.
* Maintains the desired replica count.

## Choosing Docker Images

### Use Official Images

Examples:

```dockerfile
FROM nginx:latest
FROM postgres:16
FROM node:22
FROM python:3.12
```

### Use Specific Versions

Recommended:

```dockerfile
FROM python:3.12
```

Avoid:

```dockerfile
FROM python:latest
```

### Use Smaller Variants

```dockerfile
FROM python:3.12-slim
FROM node:22-alpine
```

Benefits:

* Faster downloads
* Reduced storage usage
* Improved security

### Match the Runtime

| Application  | Recommended Image                   |
| ------------ | ----------------------------------- |
| Python       | python:3.12                         |
| Node.js      | node:22                             |
| PostgreSQL   | postgres:16                         |
| Nginx        | nginx:latest                        |
| ASP.NET Core | mcr.microsoft.com/dotnet/aspnet:8.0 |

## Summary

Docker Swarm is Docker's built-in orchestration platform used to deploy, manage, and scale containerized applications across multiple machines. It provides clustering, service management, load balancing, self-healing, and rolling updates while maintaining a simple setup and learning experience.
